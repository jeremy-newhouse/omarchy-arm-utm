Build Omarchy ARM

Omarchy 4 cannot be installed on ARM64. This rebuilds its desktop on top of Arch Linux ARM, in a native aarch64 virtual machine accelerated with HVF, from macOS with a single command.

I just want the VM

Download omarchy-arm-utm-v2.zip from the Internet Archive (3,6 GB), double-click, and it boots on its own.

10 minutes + the download

I want to build it myself

./build-omarchy-arm.sh and answer with Enter, except for three decisions.

1 h — 1 h 50

1 What you need

Mac with Apple Silicon The VM is native aarch64 with HVF. On Intel you'd have to emulate, and it would take a day. uname -m → arm64
Homebrew The script installs qemu, expect, and aria2 if missing. brew --version
UTM 4.7 or later This is where the virtual machine gets registered. brew install --cask utm
Command Line Tools This is where git and python3 come from, which the script uses to compute the package list. xcode-select -p
~40 GB free The working directory peaks around 24 GB, and APFS clones can push it higher. df -h ~
Decent connection Downloads ~900 MB of base images, then around 1.500 packages from the Arch Linux ARM repos. —

If something is missing:

# git and python3
xcode-select --install

# Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install --cask utm
No sudo needed. The script doesn't touch anything on the host system: everything it needs, it writes inside its working directory, and the three Homebrew dependencies install under your user.

2 What context it needs

None: it's a single file. build-omarchy-arm.sh carries the fifteen files it needs embedded inside it —the three install stages, the sanitizer, the repair tool, the optional-apps installer, the update hook, the VM configuration, the two expect harnesses, the QEMU launcher, and the .utm bundle generator—, plus the README.md that ships inside the zip. It writes them to disk on startup. You can copy just that one file to another Mac and it will work the same.

The only thing you can hand it ahead of time, to save yourself ~900 MB of download, are the base images: 

mkdir -p ~/omarchy-arm-build/dl
cp alpine-virt-*-aarch64.iso     ~/omarchy-arm-build/dl/alpine-virt-aarch64.iso
cp ArchLinuxARM-aarch64-*.tar.gz ~/omarchy-arm-build/dl/alarm-rootfs.tgz

The working directory is ~/omarchy-arm-build unless you point it elsewhere with W=/path/you/want.

3 Running it

$ ./build-omarchy-arm.sh

And that's it. With a terminal, it first asks six questions pre-filled with what it detects about your Mac, so you can answer them with Enter: 

━━━ configuration ━━━
  Timezone [Europe/Madrid]:             ← from /etc/localtime
  Keyboard (console) [es]:              ← from macOS preferences
  Keyboard (Hyprland/Wayland) [es]:
  Cores for the VM [6]:                 ← half your performance cores
  Memory for the VM (MiB) [12288]:      ← based on your RAM
  Disk size [80G]:

And then the three that do change the outcome:

Build the 17 Omarchy tools that don't exist for ARM?

If you say no, the desktop still works, but ttfx (the screensaver), tensaku (annotate screenshots), omacalc, omacut, omawrite, aether, cliamp, and omarchy-nvim will be missing. They can be added later with yay -S.

+40 min

Include OBS Studio and Pinta?

They're free software, so they can travel inside the image, and the one that ships includes them. OBS is compiled entirely from source (without the browser plugin, whose CEF is x86-only), and Pinta needs Microsoft's official arm64 .NET. It's the most expensive part of the whole process.

+50 min

Prepare the image for distribution?

No leaves the VM with your user and your configuration, and skips the sanitize and package phases. Yes renames the user to omarchy, deletes SSH keys, git identity, and histories, and generates a .zip with its sha256.

+13 min

To skip answering anything:

$ ./build-omarchy-arm.sh --yes   # doesn't ask: builds the image ready for distribution

Without a terminal —cron, CI, nohup— it also doesn't ask: it detects there's no tty and continues in unattended mode.

4 How long each phase takes

Measured on a real build on an M3 Max, with the tools compiled and without OBS or Pinta.

deps~10 s checks the Mac and installs qemu, expect, and aria2 if missing
fetch2 min downloads Alpine and the ALARM rootfs, verifying sha256 and MD5
prepare~10 s cross-references Omarchy's live branch against the Arch Linux ARM index
build40 min Alpine headless, partitioning, rootfs, and the three stages in chroot
utm1 min writes the .utm bundle and registers it in UTM
verify4 min boots it and requires seven conditions: Hyprland and quickshell alive, ≥400 commands, ≤5 broken links, ≥6 units, version 4, and full clipboard
sanitize10 min copies the disk and cleans it up for distribution
package3 min compacts the qcow2, creates the bundle, and compresses it
76–83 min total → 3,6 GB of .zip ~24 GB peak on disk with OBS and Pinta included

The build phase prints almost nothing while it works. To see inside it: 

$ tail -f ~/omarchy-arm-build/logs/build.log

5 If something fails

Every phase is resumable, so you never have to start from scratch:

$ ./build-omarchy-arm.sh --from build    # resume from there
$ ./build-omarchy-arm.sh --only package  # repeat just one phase
$ ./build-omarchy-arm.sh --list          # see the valid names

Resuming doesn't ask again: it reuses what you already decided. Logs live in ~/omarchy-arm-build/logs/, one per phase. The build one is the one that matters: it carries the full output of the three stages inside the guest, with the [stage1], [stage2], and [stage3] prefixes.

Three deliberate behaviors

  • If a disk is already built, build doesn't delete it: it moves it to omarchy-arm.qcow2.previous and starts a new one.
  • If a VM with the same name already exists in UTM, it doesn't delete it: it registers the new one by appending the time to its name.
  • For UTM to recognize a new bundle, you have to restart the app, because it only scans Documents on launch. If you have VMs running, the script warns you and lets you decide; in unattended mode it doesn't stop them, and tells you to import the bundle by hand with File → Import.

6 When it's done

The VM appears in UTM and boots on its own, without asking for a password.

The Option key (⌥) acts as SUPER, because macOS intercepts Cmd before UTM receives it. ⌥+Space opens the Omarchy menu, ⌥+Return a terminal, ⌥+K the full list of shortcuts.

Proprietary apps don't ship inside —bundling them would mean redistributing third-party binaries— but they all have an official ARM64 build, and the image includes an installer that downloads them from their source: 

$ omarchy-arm-extras --list
$ omarchy-arm-extras          # interactive menu

1Password, Obsidian, Typora, LocalSend, and Google Chrome. Spotify has no native ARM client, but the web version does work: it needs Widevine, which comes bundled inside Google Chrome arm64.

7 If you don't want to build it

The image all this produces is published, sanitized, and ready to import: 

# https://archive.org/details/omarchy-arm-utm
# download omarchy-arm-utm-v2.zip — 3,6 GB
$ shasum -a 256 -c omarchy-arm-utm-v2.zip.sha256
$ unzip omarchy-arm-utm-v2.zip
$ open "Omarchy ARM.utm"

User omarchy, password omarchy (root too).

Next to it there's an omarchy-arm-utm.zip of 6,5 GB: it's the first release, and it keeps the short name so the links and checksums published with it keep pointing at the exact bytes they were written for. That's the only reason the current one carries -v2 in its name. If you already downloaded that one, you don't need to pull 3,6 GB again: the two scripts in fixes/ bring it up to date from the inside.

8 To undo it

$ rm -rf ~/omarchy-arm-build   # the entire working directory

And delete the VM from UTM's own interface. The script hasn't touched anything else on your Mac.
